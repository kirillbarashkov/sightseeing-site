# Классные места — генератор сайта

Статический сайт со списком направлений для путешествий.
Источник данных — заметки Obsidian, помеченные тегом `#public`.

**Живой сайт:** https://kirillbarashkov.github.io/sightseeing-site/

## Как это работает

```
Obsidian vault (D:\...\02-Sightseeing\Places\*.md)
        │
        │  python build.py
        ▼
site_build/                  ← готовый статический сайт
    index.html               ← сетка карточек
    places/<slug>.html       ← страница на каждое место
    assets/style.css
        │
        │  git push origin gh-pages
        ▼
GitHub Pages
```

Markdown рендерится **на этапе сборки** (Python-модуль `markdown`), поэтому
на сайте нет клиентского JS и ничего не ломается в браузере.

## Требования

- Python 3.10+
- `pip install pyyaml markdown`

## Проверка (линтер)

```bash
python check.py            # ошибки + предупреждения, код возврата 1 при ошибках
python check.py --strict    # предупреждения тоже валят проверку
python check.py --quiet     # только итоговая строка
```

Линтер обходит обе папки-источника и печатает **все** замечания сразу, а не
останавливается на первом, как сборщик:

- **ошибки** — сборка точно упадёт: кривой YAML, дата не разобрана или
  повторяется, нет раздела `## Расписание`, кривая строка таблицы, незнакомый
  тип (не `день`/`вечер`/`без меня`), ссылка не `http(s)`, файл картинки не найден;
- **предупреждения** — собрать можно, но что-то поедет: заметка без `#public`
  (на сайт не попадёт), ссылка `[[…]]` на непубличную или несуществующую
  заметку (на сайте станет обычным текстом), картинка без подписи, место,
  которое не упоминает ни один день.

Полезный порядок работы: `python check.py && python build.py`.

## Сборка

```bash
python build.py
```

Скрипт читает обе папки-источника, отбирает заметки с тегом `public` в
YAML-свойстве `tags`, и полностью пересобирает `site_build/`. Пустые поля не
выдумываются — если `best_season` или `estimated_cost` не заполнены, они просто
не показываются.

Сборщик строгий: любая кривая заметка **останавливает сборку целиком**
(`BUILD ABORTED`), и тогда `site_build/` не трогается вообще. Лучше упасть, чем
опубликовать сайт без одного дня.

## Как это работает — вкладка «Леночка приезжает»

```
05-Lenochka-coming/
    Intro.md              ← письмо и подзаголовок
    Days/YYYY-MM-DD-*.md  ← день: расписание таблицей в теле
    Places/*.md           ← отель, театр, ресторан, причал
    Assets/*.jpg          ← картинки (сборщик копирует их в site_build)
        │
        │  python build.py
        ▼
    lenochka.html                     ← карточки дней
    lenochka/den-NN.html              ← страница дня: таймлайн + фото
    lenochka/<slug>.html              ← страница места
```

## Схема заметки дня

```markdown
---
title: Пешком через центр
date: 2026-11-09
mood: "Понедельник не повод сидеть в отеле: идём пешком."   # строка курсивом
image: Assets/den-04-zaryade.jpg                            # карточка + обложка дня
image_credit: "Фото: DmitriyGuryanov, CC BY-SA 4.0"
image_credit_url: https://commons.wikimedia.org/wiki/File:…  # источник подписи
hotel: "[[Сафмар Аврора Люкс]]"
tags: [lenochka, public]
---

# Пешком через центр

## Расписание

| Время | Что | Тип |
| --- | --- | --- |
| 12:00 | Выходим из [[Сафмар Аврора Люкс]] пешком | день |
| 19:00 | Яхта «Дегустационный сет» | вечер |
| вечер | Ужин в отеле — ты там ужинаешь | без меня |

## Куда по дороге забежать
- обычный текст дня, что угодно
```

**Почему расписание в теле, а не в свойствах:** панель «Свойства» в Obsidian
умеет только плоские значения (текст, список, число, дата). Список объектов ей
не отрисовать, поэтому таймлайн жил «под капотом» и в Obsidian был не виден.
Таблица в теле видна и правится как обычный текст.

Колонка **Тип** задаёт вид блока на сайте: `день` — обычная строка,
`вечер` — тёмный блок с золотом (наш вечер), `без меня` — тихий светлый блок
(её вечер без меня). Пустая ячейка = `день`.

## Схема заметки места

```markdown
---
title: Рыба моя
category: Ресторан
status: Забронировать
time: "8 ноября, после театра"
address: Славянская площадь, 2 (метро Китай-город)
tags: [lenochka, public]
---

# Рыба моя

текст о месте…

## Ссылки
- [Сайт](https://rybamoya.ru/)
- [Карта](https://yandex.ru/maps/?text=Славянская площадь 2)
- [Билеты](https://afisha.yandex.ru/…)
```

`## Ссылки` превращается в чипы «Сайт / Карта / Билеты». Подписи только эти три;
`Карта` подставляется автоматически из `address`, если её не указать. Внутри
`## Ссылки` — только строки вида `- [Подпись](https://…)`, иначе сборка упадёт.

## Схема заметки места (первая вкладка)

```yaml
---
category: Природа            # Природа | Город | Событие
status: Планируется          # Планируется | Отслеживание | Посещено
priority: Must visit         # Must visit | Nice to have
estimated_cost:              # заполняется вручную, не выдумывается
best_season: Лето
location: Сахалинская область
links:
  site: https://...
  maps: https://yandex.ru/maps/...
tags: [sightseeing, russia, public]   # public = публикуется на сайте
---
```

Тег `public` определяет видимость на сайте. Убрать его — заметка исчезнет
из сборки, оставаясь в Obsidian.

## Публикация

```bash
# 1. собрать
python build.py

# 2. выложить (из чистой копии site_build/)
git push -f origin gh-pages
```

Ветка `gh-pages` содержит **только** результат сборки. Исходники живут в `main`.

> ⚠️ Никогда не делай `git merge` между `main` и `gh-pages` — истории не связаны,
> в `index.html` попадут маркеры конфликта и сайт сломается. Ветки независимы.

## Настройки GitHub Pages

`Settings → Pages → Source: Deploy from a branch → gh-pages → / (root)`
